# Source repositories

Read on 2026-11-25. Each row says what this skill took and what it left.

| Repository (commit read) | What it is | Taken | Left |
|---|---|---|---|
| [solarssk/video-describer](https://github.com/solarssk/video-describer) (`d99e017c`, MIT) | Samples frames from each clip (up to 100 per video at 640 px), sends them to a paid vision API and writes one timestamped description per file, with 3 to 5 key moments marked with a star that become NLE markers. | The habit: describe every clip before cutting; one notes file per clip; `mm:ss` timestamps; star the 3 to 5 moments that matter; say "nothing notable" when that is the truth. `index` makes contact sheets (frames capped per clip) and a notes stub; the agent reads the sheets itself, so no API key is needed. | The paid providers, the web UI, Whisper transcription and NLE marker export. |
| [Schabo/orbis-reframe](https://github.com/Schabo/orbis-reframe) (`64069e7d`, GPL-3.0) | Linux editor for 360 footage (Vulkan): stitching from the per-file MEI calibration, gyro stabilisation, keyframed reframing. `docs/formats/insta360-x5.md` documents the X5 files. | The X5 facts in [insta360-360.md](insta360-360.md): `.insv` holds two fisheye streams, the `.lrv` proxy holds both fisheyes side by side (lens 0 on the right), full-range BT.709, the camera clock in the file name. Reframing as keyframed yaw, pitch and field of view, plus a tiny-planet view. No code is copied (GPL). | The stitch itself. `v360 input=dfisheye` is an approximate stitch: it ignores the per-file calibration and parallax, so the seam can show. For a clean seam, horizon lock or stabilisation, use orbis-reframe on a Linux GPU host, or Insta360 Studio. |
| [sheldonxxxx/insta360-ai-toolkit](https://github.com/sheldonxxxx/insta360-ai-toolkit) (`1577a97f`, MIT) | Agent skill for Insta360 photos (`.insp`) through the Insta360 MediaSDK, which needs a licence. | Its habits: originals stay read-only; a recipe file beside every output (inputs, options, result); a successful exit or a decodable file is not proof, so check pixels (not blank, right size) and look at the result. `render` writes `<stem>.recipe.json`, `verify` samples frames for blank pictures. | The SDK route. Photos are out of scope here. |
