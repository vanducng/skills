# Commit Message Standards

## Format

```
type(scope): description
```

Optional body:
```
type(scope): description

<1-2 sentences on WHY, not WHAT>

Refs #123
Closes #456
```

## Types (in priority order)

| Type | Use for |
|---|---|
| `feat` | New user-facing feature |
| `fix` | Bug fix |
| `perf` | Performance improvement (no behavior change) |
| `refactor` | Restructure code without changing behavior |
| `docs` | Documentation only |
| `test` | Add or fix tests |
| `style` | Formatting, whitespace (no logic) |
| `build` | Build system, packaging |
| `ci` | CI/CD pipelines |
| `chore` | Maintenance, deps, config — catch-all |
| `revert` | Reverting a prior commit (see Special cases) |
| `merge` | Auto-generated by `git merge` — not for hand-written commits |

## Rules

- **≤ 72 characters** for the subject line
- **Imperative present tense** — "add" not "added", "fix" not "fixes"
- **No trailing period**
- **Scope is optional but preferred** — match the directory or feature, not the file
- **Focus on WHAT, not HOW**
- For changes inside `.claude/` (skills, agents, hooks), use `feat`, `fix`, or `perf` with scope `skill` — not `docs`
- **Never mix `refactor:` with `feat:`/`fix:` in one commit.** A behavior change hidden inside a restructuring diff is unreviewable — split them so each commit is one type (see `vd:simplify`)

> **PR titles are the exception** — they use **past tense (v-ed)** because they describe what the branch did (e.g. `feat(auth): added OAuth2 provider`). Commit messages stay imperative. See `workflow-pr.md`.

## Never include

- AI attribution: ❌ "Generated with Claude", ❌ "Co-Authored-By: Claude"
- Emoji unless explicitly requested by user
- Ticket IDs in the subject — put them in the body (`Refs #123`, `Closes #456`)
- Branch names in the subject

## Good examples

- `feat(auth): add login validation`
- `fix(api): resolve query timeout`
- `docs(readme): update install guide`
- `refactor(utils): simplify date logic`
- `chore(deps): bump react to 19.0`
- `perf(skill): trim docs reference files`
- `ci(release): pin actions to SHA`

## Bad examples

- ❌ `Updated files` — not descriptive, not conventional
- ❌ `feat(auth): added login using bcrypt with salt and rate limiting` — too long, describes how
- ❌ `Fix bug` — not specific
- ❌ `feat: 🚀 ship new dashboard` — emoji, no scope
- ❌ `fix(api): resolve query timeout (issue #123)` — issue ref belongs in body

## Special cases

| Surface | Format |
|---|---|
| Skill update in `~/.claude/skills/` or `~/skills/skills/` | `feat\|fix\|perf(skill): <description>` |
| New skill | `feat(skill): add <skill-name>` |
| Release | `chore(release): <version>` |
| Revert | `revert: <subject of reverted commit>` + body `Reverts <sha>` |
| Merge | `merge: <from> into <to>` (auto-generated by `git merge`) |
